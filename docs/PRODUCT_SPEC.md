# 产品需求：助手角色与会话管理 / 分类式设置（v0.2）

> 依据 2026-11-14 产品评审（用户拍板）。四项需求纳入下一版开发，
> 优先级见 §5。总体结论：三 AI 独立入口不变（ADR-005），本版解决
> **角色管理、会话管理、设置分层**三个层次。

## 1. 大肥鱼：多角色聊天应用

定位：**多角色聊天应用**（非固定角色客户端）。每个角色独立会话空间，
切换角色不丢失历史。

### 1.1 角色选择界面

「大肥鱼 · 角色」页：预设角色列表（头像/名称/描述/当前使用标记）+
「角色配置」入口（新增/修改名称、模型、系统提示词、声音、形象）。

### 1.2 角色预设字段

| 字段 | 说明 |
|------|------|
| profile_id | 稳定唯一 ID |
| name | 角色名称 |
| avatar_id | 角色形象 |
| provider_id / model_id | 模型供应商和模型（经 Bridge Model Router） |
| system_prompt | 角色设定 |
| voice_id | 语音配置 |
| context_config | 上下文策略 |
| is_default | 默认角色 |

### 1.3 角色与会话解耦

- 同一角色可有多个会话；不同角色上下文不混淆。
- 切换角色 → 进入该角色自己的会话历史；切回 → 原历史完整保留。
- **切换时若在语音交互中，先停止当前音频会话再切换**（Audio Manager
  独占，ADR-005）。

### 1.4 数据结构

```text
AssistantProfile
    ├── profile_id
    ├── name
    ├── model_config
    └── avatar_config

Conversation
    ├── conversation_id
    ├── profile_id
    ├── title
    ├── created_at
    ├── updated_at
    └── messages[]
```

## 2. 小智：Agent 展示与切换（两阶段）

区分两个概念：**智能体 Agent**（后台配置的角色/模型/提示词/声音）与
**设备 Device**（绑定到 Agent 的硬件）。官方未提供"设备端随时切换
已绑定 Agent"的标准接口。

### 2.1 第一阶段：前台展示当前智能体

小智页顶栏/卡片展示：已连接状态、当前 Agent 名称（如"小智·温柔助手
/官方云端智能体"）、当前音色。切换按钮禁用（标注"待接口支持"）。

### 2.2 第二阶段：多 Agent 切换（依赖官方能力验证）

若官方支持多 Agent 绑定切换：Agent 列表 → 当前标记 → 切换确认 →
重连 → 声音/表情/角色信息同步。若不开放：用户在官方后台完成绑定，
**设备只展示当前状态**。

> ⚠️ 不得直接改设备本地 Agent ID 视为切换成功——云端绑定关系与
> 鉴权未同步即未切换。实现方案（官方代理 vs 自建 server）见
> [XIAOZHI_PROTOCOL.md §4](XIAOZHI_PROTOCOL.md)。

## 3. 会话管理：统一 UI，分层实现

三助手统一会话管理 UI；底层按服务能力各用不同存储策略。

### 3.1 能力矩阵

| 功能 | 大肥鱼 | Muse | 小智官方云 |
|------|--------|------|------------|
| 新建会话 | ✅ | ✅ | 不承诺 |
| 历史列表 | ✅ | ✅ | 以官方能力为准 |
| 切换会话 | ✅ | ✅ | 不承诺 |
| 重命名 | ✅ | ✅ | 不承诺 |
| 删除会话 | ✅（二次确认） | ✅（二次确认） | 不承诺 |
| 上下文压缩 | 自动 | 自动 | 由官方服务决定 |
| 本地查看记录 | ✅ | ✅ | 可考虑本地缓存 |
| 会话导出 | 后续（JSON/TXT） | 后续 | 不承诺 |

### 3.2 上下文压缩（大肥鱼/Muse）

**会话历史 ≠ 模型上下文**，二者不绑定：

- 保留完整历史消息（用户可随时查看）。
- 上下文窗口不足时系统生成阶段性摘要。
- 后续请求 = 摘要 + 最近若干轮消息。
- 第一版仅自动压缩；手动压缩/摘要编辑放后续。

```text
Conversation
    ├── messages
    ├── summary
    ├── context_window
    ├── last_compacted_at
    └── compact_version
```

禁止直接删除早期消息来"压缩"。

### 3.3 小智会话边界

官方 WS 协议的 `session_id` 是**通信会话标识**，不是长期聊天记录 ID。
官方控制台可查单 Agent 聊天记录；设备端创建/删除/压缩历史的完整接口
未公开。小智第一版只维护当前通信状态与最近交互（本地缓存），
**不伪造多会话管理**。

## 4. 分类式设置（设置首页 + 分类详情页）

480×480 空间有限，设置分层避免单页堆砌。

### 4.1 设置首页

四入口卡 + 底部固件状态行：

- 显示与声音（音量/亮度/息屏）
- 网络与连接（Wi-Fi 状态、重新配网、两个二维码、设备绑定、网络诊断）
- 服务管理（订阅刷新策略入口；**具体周期在订阅中心管理**，档位
  5 分钟/15 分钟/30 分钟/1 小时/6 小时；允许手动刷新）
- 设备信息（版本/内存/硬件）

### 4.2 设备信息页（硬件监控）

数值由固件运行时采集（**禁止静态配置值代替**）：

| 指标 | ESP-IDF 获取方向 |
|------|------------------|
| PSRAM 总量/空闲 | `heap_caps_get_total_size()` / `heap_caps_get_free_size()`（MALLOC_CAP_SPIRAM） |
| PSRAM 最大连续块 | `heap_caps_get_largest_free_block()`（比剩余量更能预测动画解码/LVGL 分配失败） |
| 内部 SRAM | `MALLOC_CAP_INTERNAL` |
| DMA 可用 | `MALLOC_CAP_DMA` |
| Flash 分区 | `esp_partition` |
| CPU 频率 | `esp_clk_cpu_freq()` |
| 电源与电池 | AXP2101 经 Power Manager（电压/电量/充电/USB，PLAN §13.3） |

模拟器阶段显示模拟值并标注；真机（Phase 6）接真实采集。

### 4.3 二维码位置

配网页二维码与后台管理二维码放在**网络与连接**页（点击全屏大码），
不放设置首页。

| 优先级 | 功能 | 原因 |
|--------|------|------|

| P1 | 大肥鱼多角色 | 核心产品能力 |

| P2 | 会话导出和高级管理 | 后续扩展 |

## 6. 存储架构决定（ADR-006）

**大肥鱼和 Muse 的历史会话统一存储在 Gadget Bridge**；设备端只保存
最近会话列表和必要缓存；小智官方云端历史以官方服务为准。

理由：不让 16MB Flash 和 TF 卡承担大量聊天记录；方便后续从设备换到
手机/网页查看历史。数据模型与 API 见 [ARCHITECTURE.md §4a](ARCHITECTURE.md)。
